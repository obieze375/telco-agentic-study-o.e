# Competition Submission Guidelines

## Overview

For each track where the participant competes, participant must submit a single archive named:

```text
code.zip
```

The submitted `code.zip` must contain all code, model files, configuration files, and instructions needed to reproduce the participant's final results.

When executed according to the instructions provided by the participant, the submission must generate a single output folder named:

```text
result/
```

The `result/` folder must contain exactly the required output files described below.

> [!NOTE]
> IMPORTANT: The zip file should be submitted using HF (the most desirable option), git, or modelscope.


> [!NOTE]
> Participants are hihgly encouraged to submit a technical report of their solution together with the zip file.
> However, this is not mandatory and will not be considered in the eval process.
> IMPORTANT: The 3 selected winners for each track will have to also submit the technical report presenting the proposed solutions.

---

Each participant must submit:

```text
code.zip
```

This archive must include:

```text
code.zip
 README.md
```

## Required Output File

Running the submitted code must produce a folder named:

```text
result/
```

The `result/` folder must contain the following three files:

```text
result/
├── traces.json
├── results.csv
└── runtime.json
```

**No required file may be missing.**

## Required Contents of `result/`

### 1. `traces.json`

The file `traces.json` must contain the list of all completions generated by the participant's agent/workflow.

It should include every completion produced during inference, not only the final selected answers.

Recommended format:

```json
[
  {
    "scenario_id": "f9a85af9-427f-5128-aa9b-fcb591d56ef7",
    "completion_id": 0,
    "completion": "Generated completion text here"
  },
  {
    "scenario_id": "f9a85af9-427f-5128-aa9b-fcb591d56ef7",
    "completion_id": 1,
    "completion": "Another generated completion here"
  }
]
```

Each entry should clearly identify:

```text
scenario_id
completion_id
completion
```

Additional metadata may be included if useful, such as decoding parameters, model name, or confidence scores.

---

### 2. `results.csv`

The file `results.csv` must contain the final prediction for each problem.

Required columns:

```csv
scenario_id,prediction
```

Example:

```csv
scenario_id,prediction
f9a85af9-427f-5128-aa9b-fcb591d56ef7,final answer here
512df232-e8ea-5a86-ad7a-12ca46f252f8,another final answer
```

There must be exactly one final prediction per problem unless the competition task explicitly allows otherwise.

### 3. `runtime.json`

The file `runtime.json` must contain the time taken to run each problem.

Participants must use the provided `runtime_logger` decorator to record per-problem runtime. The decorator should be applied to the function responsible for generating the final prediction for a single problem. The decorated function must receive a unique `problem_id` argument.

Runtime is measured using `time.perf_counter()` and includes the full execution time of the decorated function, including preprocessing, model inference, decoding, postprocessing, and final answer selection.

The generated `runtime.json` must be included in `result.zip`. Runtime values must be reported in seconds.

```python
import json
import time
import functools
from pathlib import Path
from typing import Any, Callable, Dict, List, Optional


_RUNTIME_LOG: List[Dict[str, Any]] = []


def runtime_logger(
    problem_id_arg: str = "problem_id",
    output_path: str = "runtime.json",
) -> Callable:
    """
    Decorator for measuring per-problem runtime.

    Parameters
    ----------
    problem_id_arg:
        Name of the function argument that contains the problem ID.
        The decorated function must receive this argument either as a keyword
        argument or as a named positional argument.

    output_path:
        Path where runtime.json will be written.

    Output format
    -------------
    [
      {
        "problem_id": "problem_001",
        "runtime_seconds": 1.2345
      }
    ]
    """

    def decorator(func: Callable) -> Callable:
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            import inspect

            signature = inspect.signature(func)
            bound_args = signature.bind_partial(*args, **kwargs)
            bound_args.apply_defaults()

            if problem_id_arg not in bound_args.arguments:
                raise ValueError(
                    f"Could not find problem ID argument '{problem_id_arg}' "
                    f"in function call to {func.__name__}."
                )

            problem_id = bound_args.arguments[problem_id_arg]

            start_time = time.perf_counter()
            try:
                return func(*args, **kwargs)
            finally:
                end_time = time.perf_counter()
                runtime_seconds = end_time - start_time

                _RUNTIME_LOG.append(
                    {
                        "problem_id": str(problem_id),
                        "runtime_seconds": runtime_seconds,
                    }
                )

                Path(output_path).parent.mkdir(parents=True, exist_ok=True)

                with open(output_path, "w", encoding="utf-8") as f:
                    json.dump(_RUNTIME_LOG, f, indent=2)

        return wrapper

    return decorator
```

```python
def generate_prediction(problem_id: str, question: str) -> str:
    """
    Generate the final prediction for one problem.
    """
    # Participant inference code goes here

    return prediction
```

Then call the function once per problem:

```python
predictions = []
```


Runtime should be reported in seconds.

The runtime should measure the full inference time for each problem, including preprocessing, generation, postprocessing, and answer selection.



## Execution Requirements

Submissions must be reproducible.

First, the model will be deployed on the GPUs server using `deploy.sh`. Then, the submitted code should:

```text
1. Connect to vllm server.
2. Run inference on all provided problems with API calls.
3. Save all completions to traces.json.
4. Save final answers to results.csv.
5. Save per-problem runtime information to runtime.json.
6. Outputs results into result/ folder.
```

The run command must complete without requiring manual intervention.

---

## Validation Checklist

Before submitting, participants should verify that:

```text
[ ] The submitted file is named code.zip.
[ ] code.zip contains all required code and instructions.
[ ] All model weights are .safetensors or LoRA adapters.
[ ] The submission can be run from the provided README instructions.
[ ] Running the code produces result/.
[ ] result/ contains traces.json.
[ ] result/ contains README.md.
[ ] result/ contains results.csv.
[ ] result/ contains runtime.json.
[ ] results.csv contains one final prediction per problem.
[ ] traces.json contains all generated completions.
[ ] runtime.json contains runtime per problem in seconds.
```
---

## Disqualification Conditions

A submission may be rejected if:

```text
- code.zip is missing or incorrectly named.
- The code cannot be executed using the provided instructions.
- result/ is not produced.
- Any required output file is missing.
- Model weights are provided in unsupported or unsafe formats.
- The submission depends on unavailable private files.
- The submitted results cannot be reproduced.
- traces.json does not contain the generated completions.
- results.csv does not contain final predictions.
- runtime.json does not report per-problem runtime.
```

## **Sandbox API Integration and Execution Guide**

### **API Endpoints**

* **Command Execution:**
  * https://localhost:8080/ip/api/agent/execute
* **Device Discovery:**
  * Get Device List: http://localhost:8080/ip/api/agent/get_devices_list

### **Request Headers**

Content-Type: application/json

*(Note: The system has completely removed Token authentication; the request Header does not need to carry an Authorization field.)*

### **Command Execution API (/execute)**

| Parameter | Type | Required | Description |
| :---- | :---- | :---- | :---- |
| device_name | String | Yes | Target device hostname (e.g., AGG_SW_01). |
| command | String | Yes | Exact CLI command to execute. |
| question_number | String | Yes | Scenario or problem number (e.g., "34"). |

### **Device Discovery API (/get_devices_list)**

Used to dynamically obtain the list of all available devices for a given scenario/problem ID, in support of subsequent command dispatch.

**Request Payload:**

```
{
    "question_id": 20
}
```

**cURL Example:**

```
curl --location --request POST 'http:/localhost:8080/ip/api/agent/get_devices_list' \
--header 'Content-Type: application/json' \
--data-raw '{
    "question_id": 20
}'
```

### **Concurrency Rules**

* **Uniform 5-Way Concurrent Dispatch**: The system no longer enforces a single-concurrency lock. To ensure optimal system capacity and contestant evaluation efficiency, the system uniformly uses **5-way concurrency** during test runs and batch dispatch.
* **Rate Limiting**: The system has removed the original Token-based rate limiting and daily call restrictions. Contestants should hardcode a thread pool size of **5 concurrent workers** in their client code (e.g., max_workers=5 for Python ThreadPoolExecutor).

### **Python Usage Example**

```
import requests
import urllib3

# Disable self-signed certificate warnings (test environment only)
urllib3.disable_warnings()

def get_device_list(question_id):
    url = "http://localhost:8080/ip/api/agent/get_devices_list"
    payload = {"question_id": question_id}
    try:
        response = requests.post(url, json=payload, timeout=10)
        return response.json().get("devices", [])
    except Exception as e:
        print(f"Failed to get device list: {e}")
        return []

def execute_cmd(device, cmd, q_num):
    url = "https://localhost:8080/ip/api/agent/execute"
    headers = {
        "Content-Type": "application/json"  # No Token authentication required
    }
    payload = {
        "device_name": device,
        "command": cmd,
        "question_number": str(q_num)
    }
    try:
        response = requests.post(url, headers=headers, json=payload, timeout=20, verify=False)
        return response.json()
    except Exception as e:
        print(f"Command execution failed: {e}")
        return {}

if __name__ == "__main__":
    q_id = "34"

    # 1. Dynamically get device list
    devices = get_device_list(q_id)
    print(f"Devices found in current scenario [{q_id}]: {devices}")

    # 2. Dispatch an allowlisted command to the first discovered device
    if devices:
        target_device = devices[0]
        test_command = "display current-configuration"
        print(f"Executing command: '{test_command}' on device [{target_device}]...")
        res = execute_cmd(target_device, test_command, q_id)
        print(f"Device echo content:\n{res.get('echo', 'No output')}")
```

**Reminder on Security Mechanisms and Escape Prevention:**

Before performing command cache matching, all inputs undergo strict problem-bank, no-escalation allowlist validation. Any input that does not precisely match the allowlist will be intercepted by the underlying "CLI Error Simulation Engine" and dynamically return a realistic, vendor-specific error message (e.g., Error: Unrecognized command found).
